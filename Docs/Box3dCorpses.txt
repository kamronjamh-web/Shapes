Box3D corpse backends and comparison (2026-10-10)

Status: FpsEnemyCorpsePool now has batched cube/pyramid rendering, immutable shared
collision shapes, bounded reusable slots, and an optional background CPU Box3D
backend. CorpseWorkerEnabled selects that backend for supported fort worlds;
generic settings default to the existing Godot physics backend. North Gate enables
the worker by default and is
configured for 2,056 active corpses; generic settings retain a default of 64.
The pool allocates slots lazily and recycles the oldest when full. The tuning
menu can lower the run's limit; lowering it retires excess bodies.
Lifetime remains 4 s. The worker mode creates no per-corpse Godot rigid bodies;
Godot fallback uses shared shapes/material and the same batched visual publication.
These are cosmetic single-body cubes/pyramids, not jointed character ragdolls.
Box3D runs on the CPU, never GPU compute. A dedicated thread owns one serial native
world; gameplay deaths, lifetime, rewards, caps and rendering remain on the main
thread. Completed poses can lag simulation; this backend has no combat authority.

Production implementation:
  Scripts/Fps/Physics/Box3dCorpseWorker.cs
  Scripts/Fps/Physics/Box3dNativeWorld.cs and CorpsePhysicsTypes.cs
  Scripts/Fps/FpsEnemyCorpsePool.Worker.cs and .Rendering.cs
  Scripts/Fps/FpsVerticalSlice.CorpseWorld.cs
The main thread captures static layer-1 boxes, convex hulls and CCW triangle meshes
from known fort geometry, excluding player/core/corpses. Gate alive state and fort
geometry version invalidate the snapshot. Replacement runs on the worker and wakes
sleepers. Unsupported geometry or absent/incompatible DLL retains Godot physics.

Commands coalesce in fixed arrays for 2,056 slots, with per-slot generations and
clear epochs. Dirty commands retry instead of losing spawns/removals to contention.
Main-thread pose copies are nonblocking and reject recycled/cleared generations.
Pause is atomic, clears timing backlog, and main-thread visuals/lifetimes freeze.
The worker advances at 60 Hz/four substeps with at most .25 s pending cosmetic time;
excess/contended time is reported as dropped, rather than blocking the game.
Frame telemetry separates worker StepMs and ReadMs from main-thread publication.
Shutdown joins the owning thread before disposing the world; no per-frame native
Step wait is introduced. Managed/native failures select the Godot fallback.

Comparison method:
The Godot side uses the actual production pool and FpsHordeDeath records. Box3D
receives copied initial transforms, shape dimensions and launch/angular velocities.
Nominal mass 1, friction .65, restitution .12, effective damping .25/.45, gravity
9.8 m/s^2, 60 Hz, Box3D four substeps. Floor, ramp and wall have matched dimensions.
Both sides collide with static geometry only, with no corpse-to-corpse contacts.
The diagnostic lifetime is 15 s to preserve samples through the measurement.

Box3D defaults enable continuous collision (pinned src/types.c); dynamic-versus-
static CCD is active without setting isBullet. The thin-wall test launches a .1 m
cube at 24 m/s toward a .03 m wall. Passing this case does not establish matching
CCD behavior for every orientation/speed. Sleep, mass properties, damping/material
mixing and solver trajectories differ; four substeps are not trajectory parity.

Godot Performance.TimePhysicsProcess publishes the recent approximately-one-second
maximum, not independent per-tick times. Each phase warms for 66 ticks then records
180 distinct ticks; three monitor observations are spaced 60 ticks apart. Raw CSV
monitor values repeat between updates. Direct Box3D Step and read/visual-publication
costs are measured separately per tick. The inactive Godot pool stays frozen/hidden
in the Box3D phase. Engine observations include synchronization/harness work and
are not isolated solver timings. Never divide Godot monitor by Box3D Step as speedup.

Historical isolated-comparison limits (the measurements below used the first shim,
before production worker integration and ABI2):
- The comparison had floor/ramp/wall fixtures, not live fort terrain/gate updates.
- Its native handle storage was append-only. ABI2 now reuses generation-safe slots
  and retires them on generation exhaustion, rather than aliasing stale handles.
- The harness owned cohort lifetime; production pool lifetime remains authoritative.
- Only local i9-14900KF/RTX4070 diagnostics, not target GTX1060/RX580 hardware.
- No sustained firing, whole-horde combat, GPU cost, or 50k/45 FPS claim.

These historical results establish that Box3D can simulate the isolated corpses;
they are not a production-worker or full-combat performance measurement.
