CORPSE PERFORMANCE AND OWNERSHIP

The 2,056 active corpse limit is preserved. Corpses remain cosmetic single-body
cubes/pyramids, with the original four-second default lifetime, killing-hit launch,
overkill cap, oldest-first recycling, pause/resume and reward separation.

Rendering
---------
Two MultiMeshes share one material: one for cubes and one for pyramids. Reused
buffers carry world poses, size and linearized per-body colors. Publishing skips
unchanged poses; a sleeping body's final pose remains visible without repeated
uploads. The Godot fallback shares immutable collision shapes and one physics
material. A free-slot bitmap and chronological linked list replace pool scans
for allocation and oldest-body recycling.

Physics
-------
North Gate enables Background corpse physics by default. The control is in
Movement / deaths and can switch back to Godot physics during a run.
The Windows x64 backend owns a Box3D world on a dedicated CPU thread. This is not
GPU physics. Main-thread commands and completed poses use bounded slot arrays;
failed nonblocking command handoffs are retried. Slot generations and clear
epochs prevent stale poses from reviving recycled or cleared bodies.

The main thread copies static fort collision geometry into an immutable snapshot:
ground, terrain triangles, boxes, convex ramps and living gates. Breach, restore
and fort rebuild replace that snapshot and wake sleeping bodies. The worker
never accesses Godot scene nodes or physics/rendering servers. Player, core,
weapons, living enemies and other corpses are excluded from corpse collision.
Continuous dynamic/static collision and four solver substeps remain enabled.

Simulation uses 60 Hz steps with at most four per worker batch. Cosmetic backlog
is capped at 0.25 seconds and discarded time is measured. The main thread never
waits for a simulation result; pause, clear and teardown have explicit lifecycle
handling. Disposal joins the worker before releasing native resources. Physics
results arrive asynchronously (large death bursts can take several frames to
finish creating native bodies), and Box3D's bounce/slide details differ from
Godot's solver. Gameplay damage and rewards do not depend on corpse physics.

Unavailable native libraries, unsupported worlds/platforms and backend failures
retain the batched renderer and fall back to Godot physics. Disabling and
reenabling Background corpse physics retries the native backend. Generic worlds
default to Godot. Packaging/build details and the pinned MIT dependency are in
Docs/Box3dCorpses.txt and Native/Box3D/win-x64/DEPENDENCY.txt.

Profiling protocol
------------------
Tools/Experiments/CorpsePerformance/RunCorpsePerformance.ps1 -GodotPath <exe>
  -RunName <unique-name> [-Worker] [-SkipBuild]

Native Vulkan, 1920x1080, uncapped, i9-14900KF / RTX 4070, Godot 4.7.2 .NET,
Debug managed build. Actual North Gate collision geometry remains enabled.
Living-crowd, player and director callbacks stop; the pool receives normal physics
ticks. Fixed seed 1337 launches 2,056 alternating cubes/pyramids over the slope.
Each normal/frozen/hidden/frozen-hidden/repeated-normal phase uses the same deaths,
warms up and measures three wall-clock seconds. Live phases verify actual motion.
Frame ablations are not additive timings. Viewport GPU/render CPU include the
fort. The engine physics monitor is an interval maximum, not per-tick solver time.
Spawn timings measure synchronous enqueue/setup only and exclude deferred/native
creation and rendering work. Worker initialization occurs before spawn timings.
