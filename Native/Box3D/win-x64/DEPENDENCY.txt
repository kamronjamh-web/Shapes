Native output: .tmp/box3d-corpses/build/box3d_corpses.dll
Shim ABI version 2: body definition 84 bytes; returned state 56 bytes; Cdecl exports.
Optional build -Package stages DLL, license, dependency notice and SHA256 into
Native/Box3D/win-x64. The project copies that DLL beside the managed assembly for
deployment. Missing/incompatible native library selects the existing Godot backend.

Default dynamics collide only with static geometry; optional corpseContacts enables
dynamic/dynamic pile stress. Static category=1/mask=2, dynamic category=2/mask=1 or3.
Box sizes are full extents. Pyramid uses the same five centered vertices as production.
Mass comes from density (box volume xyz; pyramid volume xyz/3).
Body-origin linear velocity is passed at creation; pyramid center-of-mass handling,
friction mixing, damping integration, CCD thresholds, sleep and solver algorithms may
differ from Godot. Results are a comparison, not exact trajectory parity.
Handles use 16 slot bits and 15 generation bits. Storage reuses removed slots;
generation exhaustion retires a slot instead of wrapping an old handle. Batch
reads cache already-sleeping states but read the final sleep-transition pose;
geometry replacement wakes dynamic bodies and invalidates those caches.
Static triangle meshes use CCW winding. Godot GetFaces triangles must be reversed.
The isolated experiment still pauses by withholding Step. Production worker owns
the complete native world, communicates via fixed-capacity slot commands/completed
pose buffers, and uses epoch/generation filtering on the main-thread boundary.
CPU compatibility: baseline x86-64/SSE2; AVX2 kernels selected by CPUID + OS XSAVE state checks; no global AVX2/FMA requirement.
